About this archive

ranzlappen.com used to be a folder of hand-written pages on shared hosting: public_html/Project0 through Project10, plus a few strays. Some were plain HTML and JavaScript. Most of the interesting ones were PHP talking to MySQL.

The site has since been rebuilt as a Jekyll blog on GitHub Pages, and the old hosting is gone. This subdomain keeps the projects alive.

The constraint

GitHub Pages serves static files. There is no PHP interpreter, no database, no writable disk, no sessions. Anything the old code did on the server has to happen in your browser instead — or not at all.

How each kind of backend was replaced

The original did…Now it…Affects
$_SESSION for form state across page loads Keeps the same state in localStorage, so a reload still finds your work 3D Packing, Secret Image
MySQL INSERT/UPDATE/DELETE behind a form post Writes rows to localStorage through a small store that mimics auto-increment ids and timestamps Code Snippet Database, Game Lobby
File uploads into uploads/ plus a files table Stores the actual blobs in IndexedDB and lists them from there File Vault
Every player's page polling MySQL every few seconds for the shared board Holds one shared state object and pushes changes to every open tab over a BroadcastChannel Rommé, Siedler, Skat
Server-side ZIP building for a download Builds the same file in the page and hands it to you as a Blob Live HTML Editor
shell_exec() into a game server's terminal Can't, and shouldn't. Became a command builder that composes the command for you to run yourself Minecraft Command Console

What that changes for you

  • Your data stays on your machine. Nothing here has a server to send anything to. Clearing site data for this domain wipes every project's saved state.
  • Multiplayer means multi-tab. The card and board games share a table between tabs of the same browser. Open one window per player, or pass a laptop around. They no longer sync between different devices, because there is nothing in the middle to sync through.
  • Logins are gone. The old accounts, approval emails and admin dashboards guarded a shared database. With no shared database there is nothing to guard, so the projects that had a login now just start.

Two things that were quietly broken

The originals are archived as-is in the repository, but two behaviours were not worth reproducing faithfully:

  • The password-gated image checked a passphrase in PHP and then served the file — but also unlocked itself for anyone who put ?12345? in the URL. The rebuild encrypts the image with AES-GCM using a key derived from the passphrase, so a wrong passphrase genuinely cannot produce the picture.
  • The Minecraft console passed user input into shell_exec(). It is not reproduced. The page builds commands for you to paste instead.
